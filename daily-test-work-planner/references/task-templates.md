# 测试事项分类与拆解模板

按关键词初筛，最终以交付物和完成标准判定主分类。一个原始任务可拆成多个主分类，但每个执行块只保留一个主要产出。

| 分类 | 常见关键词 | 必填信息 | 规模量与拆解维度 | 典型产出 |
|---|---|---|---|---|
| 需求理解与澄清 | 看需求、熟悉业务、需求分析、澄清 | 需求/版本、范围、疑点处理方式 | 模块、角色、主流程、规则、外部依赖 | 疑点清单、业务流程、范围清单 |
| 需求评审 | 评审、技术评审、三方评审 | 评审对象、参会方、完成标准 | 模块、功能点、主流程、风险点、预计时长 | 评审意见、风险与待办 |
| 测试计划与策略 | 排期、测试方案、准入准出、风险评估 | 版本范围、测试类型、里程碑 | 模块、测试类型、人员、环境、依赖 | 测试计划、策略、排期 |
| 测试用例设计与评审 | 写用例、补用例、用例评审 | 功能范围、规则/原型、用例层级 | 功能点、流程、规则、数据组合、预计用例数 | 用例集、评审记录 |
| 环境搭建与部署 | 搭环境、部署、发版、配置 | 环境、版本/分支、组件、可用标准 | 服务、配置项、中间件、依赖、部署次数 | 可用环境、部署记录 |
| 测试数据准备 | 造数据、账号、初始化数据 | 数据用途、环境、数据约束 | 角色、状态、组合、记录数、账号数 | 数据集、账号清单 |
| 冒烟测试 | 冒烟、版本准入、构建验证 | 构建版本、环境、准入标准 | 核心流程、检查点、端、构建次数 | 准入结论、阻塞问题 |
| 功能测试 | 功测、提测、验证功能 | 模块/版本、环境、完成标准 | 功能点、主/异常流程、用例数、角色、数据组合 | 执行结果、问题单 |
| 接口测试 | API、接口联调、协议验证 | 接口清单、环境、鉴权/协议 | 接口数、方法、参数组合、状态码、上下游 | 接口结果、问题单 |
| 兼容性与适配测试 | 浏览器、机型、系统、分辨率、适配 | 平台矩阵、范围、通过标准 | 浏览器、OS、机型、分辨率、功能点 | 兼容矩阵、问题单 |
| 性能与稳定性测试 | 压测、负载、并发、容量、稳定性 | 指标目标、场景、环境、数据量 | 场景、接口、并发梯度、持续时间、指标 | 性能报告、瓶颈清单 |
| 安全测试 | 权限、越权、漏洞、渗透、敏感数据 | 安全范围、角色、合规标准 | 角色、接口、攻击面、规则、数据类型 | 风险清单、验证结果 |
| 自动化测试 | 写脚本、维护脚本、流水线 | 框架/项目、覆盖范围、运行目标 | 用例/接口数、页面数、数据组合、脚本复杂度 | 脚本、运行报告 |
| 预研与技术验证 | 预研、调研、PoC、方案验证、工具选型、自动化检索 | 预研目标、应用场景、验证对象、完成标准 | 子任务、验证点、数据源/仓库、工具/接口、样例数 | 预研结论、PoC脚本、方案记录、风险清单 |
| 缺陷提交与跟踪 | 提bug、定位、跟踪、协助排查 | 现象、环境、期望、证据 | 缺陷数、复现步骤、日志源、协作方 | 缺陷单、定位材料 |
| 缺陷验证与回归 | 验bug、回归、复测 | 缺陷清单、修复版本、关联范围 | 缺陷数、关联模块/流程、回归用例数 | 验证结论、回归结果 |
| 探索性与专项测试 | 探索、弱网、异常、易用性、安装升级 | 测试章程、范围、时间盒 | 场景、风险点、平台、时间盒 | 探索记录、问题清单 |
| 发布验收与上线检查 | 验收、上线、发布、生产检查 | 发布版本、窗口、检查/回滚标准 | 发布项、检查点、核心流程、环境 | 发布结论、检查记录 |
| 线上验证与监控 | 生产验证、线上巡检、监控 | 生产范围、安全限制、观察指标 | 核心流程、指标、日志源、观察时长 | 验证结论、异常记录 |
| 测试报告与复盘 | 测试报告、总结、复盘、质量分析 | 统计范围、受众、结论口径 | 模块、用例、缺陷、风险、指标 | 报告、复盘行动项 |
| 协作会议与支持 | 站会、同步会、联调、答疑、支持 | 议题、参与方、期望结论 | 议题数、系统数、问题数、会议时长 | 决议、责任人与截止时间 |
| 学习与流程改进 | 学习、调研、规范、工具优化 | 学习/改进目标、应用场景 | 主题、资料、实验数、受影响流程 | 笔记、方案、试验结论 |

## 通用模板

对任一分类，至少获得以下信息：

```text
对象/版本：
范围：模块、流程或功能点
环境/平台：
交付物或完成标准：
规模量：至少一项可计数指标
截止时间与依赖：
复杂度/风险：低、中、高及原因
```

## 匹配规则

1. 交付物优先于关键词。例如“评审测试用例”主分类是测试用例设计与评审，不是需求评审。
2. “测试某功能”只能匹配到候选分类，必须追问测试类型、范围、环境和规模。
3. 同一句含前后置工作时拆开。例如“部署后测试登录”拆为环境部署和功能测试。
4. “跟进、处理、支持、优化”不构成可执行动作，必须追问对象、结果和数量。
5. 同一缺陷的定位、修复确认和关联回归可拆为缺陷跟踪与缺陷验证回归。
6. 预研类工作按“大任务-子任务”输出即可，例如检索链路、样例验证、指标方案、结论沉淀；不要拆成读取文件、解析字段等过细步骤，除非用户明确要求。
