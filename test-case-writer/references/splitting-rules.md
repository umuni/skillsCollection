# 测试点拆分 / 合并规则

第一阶段拆解测试点时，粒度判断必须遵守以下规则。

## 总体原则

测试用例数量应尽可能多，而不是尽可能少。禁止将多个不同场景、不同输入条件、不同状态、不同按钮行为合并为一条用例——除非落在下方明确列出的"允许合并"范围内。

## 允许合并为一条用例的情况

- **单条件查询**：同一页面所有单字段查询，合并为一条"查询功能验证"
- **重置**：同一页面的重置操作，合并为一条"重置功能验证"
- **必填项校验**：同一页面全部必填项，合并为一条"校验页面基础字段合法性"
- **数据回显**：同一页面所有字段回显，合并为一条

查询类用例的合并方式：
- 所有单条件逐个模糊查询 + 所有查询条件全组合后的组合查询 + 所有单条件逐个精准查询，合并为最少的几条用例，而不是逐字段拆开。

校验类用例（必填、格式、类型、回显）按**页面维度**合并，而不是按字段维度拆开。

## 必须独立拆分的情况（业务判定点）

- **权限与隔离锁**：不同角色/部门的可见性差异、操作权限限制，必须独立拆分。例：A 部门不可见 B 部门数据。
- **后端逻辑拦截锁**：涉及后端逻辑判定通过后才允许执行的操作，必须独立拆分。例：进度不足拦截预约、关联数据禁止删除。
- **状态与行为锁**：见下方"状态/按钮行为拆分"，每个状态流转节点、不同状态下按钮的显隐/可用性，必须独立成条。
- **业务分支流**：正常流、异常流、补偿流（如补考）必须作为独立 ID 存在。

## 状态 / 按钮行为拆分

若列表中不同状态对应不同按钮可见性或可用性，每个状态必须独立拆分为一条测试点。

示例：
- 状态 = 预警中：解除按钮可用、恢复按钮禁用或隐藏
- 状态 = 手动解除：恢复按钮可用、解除按钮禁用或隐藏
- 状态 = 自动解除：两个按钮均禁用或隐藏

即：每个状态 = 一条独立测试用例。

## 字段校验拆分

每个字段的每一类校验项必须独立形成测试点，包括但不限于：
- 必填校验
- 长度限制
- 类型校验
- 格式校验
- 唯一性校验
- 文件大小、文件类型、文件名长度
- 字段回显

## 流程状态拆分

每个状态流转必须独立拆分为一条，例如：
- 待提交 → 已提交
- 待审批 → 审批通过
- 待审批 → 审批驳回
- 待评价 → 评价中
- 评价中 → 已归档

## 禁止跨页面合并

禁止以"通用组件"为由省略任何一个子模块的查询/重置/分页测试点——即使多个页面用的是同一套通用组件，每个子模块仍需各自保留对应测试点。
