## 生成轮次

按以下顺序在大纲锁定前补充测试点。每轮继承前轮结果，可以新增、拆分和调整候选测试点；完成 Final 后才分配 TC 编号并锁定大纲。大纲锁定后不得再追加测试点，只能做一致性核对。

1. **需求提炼**：为每个功能点记录业务规则、输入字段、字段约束、预期行为、边界条件和图片来源。
2. **核心流程**：创建、编辑、提交、审批、关闭、查询等主业务闭环；同时检查页面基础 UI 模式。
3. **测试设计方法**：对每个字段和业务规则执行等价类划分、边界值分析、场景组合和界面交互验证。
4. **L1 规范补充**：逐条检查 `references/l1-checklist.md` 的 75 项，已覆盖的不重复，适用但未覆盖的才补充；无法从需求验证的项目记录为待外部验证。
5. **Final 兜底**：去重、标题修正、模块层级修正、状态/权限覆盖复核和三锁校验。以上轮次必须在大纲锁定前完成。

## 图片与流程图

对每张图片记录：类型、核心描述、关键节点/字段、分支条件、状态变化、可见按钮、提示文案和引用章节。优先识别：

- 流程图：每条路径、分支、回退、驳回、补偿和终态；
- UI 原型：入口、字段、默认值、控件行为、列表分页排序筛选、空态和反馈；
- 架构/数据图：角色边界、依赖失败、数据同步和权限隔离；
- 表格/图表：列展示、格式、排序、空数据、极值和联动。

图片无法确认文字或行为时标记为待确认，不把视觉推断写成确定需求。

## 通用 UI 检查

按需求或原型实际存在的页面/子模块逐项检查，至少覆盖：

| 类别 | 检查点 |
|---|---|
| 列表 | 默认排序、分页首末页、总数、空数据、刷新、加载态 |
| 查询 | 单条件、组合条件、模糊/精确、空结果、重置、条件联动 |
| 表格 | 列顺序、长文本截断与完整展示、格式、横向滚动、排序 |
| 表单 | 正向提交、编辑回显、必填、长度、类型、格式、唯一性、取消 |
| 交互 | 防重复点击、成功/失败提示、二次确认、按钮显隐/禁用 |
| 数据 | 保存后回显、列表更新、详情一致性、筛选与排序联动 |
| 异常 | 网络异常、超时、服务失败、并发冲突、恢复后重试 |

只有需求、原型/截图、接口或架构说明、验收标准或项目规范表明该页面存在对应能力时才落具体用例；不存在的控件、专项能力或质量指标不凭空生成。

## 命名与去重

标题沿用原技能格式：P0/P1/P2 必须以“功能验证”或“流程验证”结尾，P3 必须以“校验xxx”开头。标题保留三级子模块前缀，并优先表达“模块-动作-条件-可观察结果”；使用登录、提交、上传、删除、搜索、切换、校验等具体动词，避免“正常”“合理”“适当”。

命名格式保持不变不代表测试点必须合并。每个不同的输入、角色、状态、分支、按钮行为或可观察预期都可以拥有独立标题，只需在标题末尾或开头遵守上述优先级格式。

默认不合并候选用例。只有在角色、状态、权限、输入条件、业务分支、操作路径和预期均等价时才可合并；Jaccard 或其他相似度只能作为候选提示，最终以业务判定差异为准。

## 质量门禁

提交阶段 1 前确认每个需求模块至少有来源，并完成 75 项 L1 逐项检查；阶段 2 前确认每条测试点有可执行路径；导出前确认：

- ID 连续且三阶段完全一致；
- 阶段 1 数量 N = 阶段 2 用例数 = `EXPECTED_TOTAL`；
- 每条步骤与预期逐行对应、可观察、无模糊词；
- P0/P1 主链路、角色权限、状态分支、字段校验和异常场景均有覆盖；
- L1 适用项均有现有用例覆盖或新增补充，重复项未重复生成，不适用项有原因记录；
- 安全、兼容性、可访问性、性能和灾备场景均能追溯到需求、原型、接口/架构、验收标准或项目规范；没有证据的项目只记录为待专项验证；
- Final 和 L1 补充已在大纲锁定前完成，锁定后没有新增、拆分、合并、删除或重排测试点；
- Excel 模板文件与原始模板一致，只填充 `TEST_CASES_DATA` 和 `EXPECTED_TOTAL`；
- Excel 字段顺序、固定空值、默认值和脚本模板逻辑未被修改。

覆盖率优化只发生在导出前。先建立“需求来源 → 测试点 → 详细用例 → 模板数据”的追踪链，逐项检查核心流程、角色权限、状态分支、字段规则、异常恢复和 UI 交互；确认覆盖充分后，再把结果原样填入既有模板。
