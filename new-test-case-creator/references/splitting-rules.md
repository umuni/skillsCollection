# 测试点拆分 / 合并规则

第一阶段拆解测试点时，粒度判断必须遵守以下规则。

## 总体原则

测试点默认按最小可验证行为独立拆分，优先保证颗粒度、可执行性和缺陷定位能力，不以减少测试用例数量为目标。禁止将不同场景、输入条件、状态、角色、按钮行为或预期结果强行合并。

合并不是强制要求。只有在验证目标、前置条件、角色权限、状态、操作路径和预期结果完全等价时，才可以酌情合并；无法证明完全等价时必须独立拆分。

## 可选合并为一条用例的情况

- **单条件查询**：仅当多个查询条件的操作路径、数据范围、结果判定完全一致时，才可合并；不同字段、匹配规则或结果表现建议独立。
- **重置**：同一页面且重置对象、默认值、联动清空和结果判定完全一致时，可合并；不同控件或不同联动行为独立。
- **必填项校验**：仅当多个字段的触发方式、提示规则、阻断行为和恢复方式完全一致时，可合并；字段规则有差异就独立。
- **数据回显**：仅当字段来源、格式化规则、空值处理和展示位置完全一致时，可合并；否则按字段或行为独立。

查询类用例的合并方式：
- 不再要求合并为最少用例。先按字段、匹配方式和组合条件识别差异，再决定是否合并；模糊查询、精准查询、组合查询和清空条件默认分别保留。

校验类用例（必填、格式、类型、回显）默认按可独立验证的规则拆分；只有页面内相关字段的触发方式、提示规则、阻断行为和恢复方式完全等价时，才可按页面维度合并。
- 页面维度合并仅作为可选策略，不得覆盖字段差异；必填、格式、类型、长度、唯一性、文件约束和回显存在不同判定时必须独立。

## 必须独立拆分的情况（业务判定点）

- **权限与隔离锁**：不同角色/部门的可见性差异、操作权限限制，必须独立拆分。例：A 部门不可见 B 部门数据。
- **后端逻辑拦截锁**：涉及后端逻辑判定通过后才允许执行的操作，必须独立拆分。例：进度不足拦截预约、关联数据禁止删除。
- **状态与行为锁**：见下方"状态/按钮行为拆分"，每个状态流转节点、不同状态下按钮的显隐/可用性，必须独立成条。
- **业务分支流**：正常流、异常流、补偿流（如补考）必须作为独立 ID 存在。

## 状态 / 按钮行为拆分

若列表中不同状态对应不同按钮可见性或可用性，每个状态必须独立拆分为一条测试点。

示例：
- 状态 = 预警中：解除按钮可用、恢复按钮禁用或隐藏
- 状态 = 手动解除：恢复按钮可用、解除按钮禁用或隐藏
- 状态 = 自动解除：两个按钮均禁用或隐藏

即：每个状态 = 一条独立测试用例。

## 字段校验拆分

每个字段的每一类校验项必须独立形成测试点，包括但不限于：
- 必填校验
- 长度限制
- 类型校验
- 格式校验
- 唯一性校验
- 文件大小、文件类型、文件名长度
- 字段回显

## 流程状态拆分

每个状态流转必须独立拆分为一条，例如：
- 待提交 → 已提交
- 待审批 → 审批通过
- 待审批 → 审批驳回
- 待评价 → 评价中
- 评价中 → 已归档

## 禁止跨页面合并

禁止以"通用组件"为由省略任何一个子模块的查询/重置/分页测试点——即使多个页面用的是同一套通用组件，每个子模块仍需各自保留对应测试点。
